# ROADMAP: интерактивная арена с управлением из Twitch Chat

## 1. Цель проекта

Создать небольшую арену в Unreal Engine, на которой зрители представлены управляемыми манекенами. Каждый манекен имеет постоянный технический идентификатор, отображаемое имя и выполняет ограниченный набор команд: перемещение к точке, приближение к другому манекену, воспроизведение анимации действия и подход к объекту.

После завершения автономной части Unreal Engine к проекту подключается отдельная программа-мост. Она читает сообщения Twitch Chat, проверяет пользовательские команды и передаёт нормализованные команды в Unreal Engine через локальное WebSocket-соединение.

## 2. Основные принципы

1. Сначала создаётся и полностью проверяется автономная система в Unreal Engine.
2. Twitch API не используется внутри Unreal Engine и не влияет на игровую логику.
3. Локальный конструктор команд использует тот же протокол, что и будущий Twitch-мост.
4. Технический идентификатор участника отделён от отображаемого имени.
5. Все входящие команды проходят проверку до выполнения.
6. У каждого манекена одновременно выполняется не более одной команды.
7. Сетевые токены и другие секреты не хранятся в Unreal-проекте и Git.
8. Формат команд версионируется, чтобы его можно было расширять без нарушения совместимости.

## 3. Границы первой версии

Первая версия должна включать:

- одну небольшую арену;
- статичные границы и навигационную область;
- одну центральную область случайного появления и именованные точки назначения;
- несколько одновременно существующих манекенов;
- базовые анимации ожидания, ходьбы и бега;
- одну тестовую анимацию удара или другого действия;
- стабильные идентификаторы манекенов;
- очередь и состояния выполнения команд;
- простые интерактивные объекты;
- локальный конструктор команд;
- текстовый JSON-протокол;
- локальное WebSocket-соединение;
- отдельную программу для Twitch Chat;
- ограничения частоты и количества команд.

Каждый манекен должен иметь:


- [ ] Ограничить максимальное количество манекенов.

### Критерий готовности

Спам, некорректные параметры и попытки управления чужими манекенами не нарушают работу арены и не позволяют вызвать произвольное действие.

## Этап TW-6. Обратная связь и наблюдаемость

### Критерий готовности

Для каждой пользовательской команды можно определить автора, преобразованный JSON, результат Unreal Engine и причину отказа.

## Этап TW-7. Сквозное тестирование

### Сценарии

- [ ] Пользователь выполняет `!join` и получает одного манекена.
- [ ] Повторный `!join` не создаёт дубликат.
- [ ] `!goto` приводит манекен в именованную точку.
- [ ] `!run @nickname` приводит манекен к движущейся цели.
- [ ] `!hit @nickname` выполняет подход, разворот и Montage.
- [ ] `!go <object>` приводит манекен к объекту.
- [ ] `!stop` корректно прерывает активное перемещение.
- [ ] `!leave` удаляет манекен и его очередь.
- [ ] Переименование Twitch-пользователя не создаёт новый `EntityId`.
- [ ] Потеря Twitch-соединения не приводит к сбою Unreal Engine.
- [ ] Потеря соединения с Unreal Engine не приводит к потере управления программой-мостом.
- [ ] Спам одного пользователя ограничивается без влияния на остальных.

### Итоговый критерий MVP

Зритель пишет разрешённую команду в Twitch Chat, программа-мост преобразует её в версионированный JSON, Unreal Engine выполняет действие соответствующим манекеном и возвращает отслеживаемый результат.

# 4. Решения, которые необходимо принять до завершения MVP

- [ ] Максимальное количество одновременно существующих манекенов.
- [ ] Требуется ли явная команда `!join` или манекен создаётся при первой команде.
- [ ] Политика очереди: ставить новые команды в очередь или заменять текущую.
- [ ] Длительность индивидуальной задержки между командами.
- [ ] Кто может задавать цель другого пользователя.
- [ ] Нужны ли ответы бота в Twitch Chat.
- [ ] Используется аккаунт канала или отдельный аккаунт бота.
- [ ] Нужна ли модераторская панель и административные команды.
- [ ] Какая анимация используется как первый `punch`.
- [ ] Должны ли состояния участников сохраняться между запусками.

# 5. Возможные расширения после MVP

- здоровье, урон, смерть и повторное появление;
- несколько типов ударов и действий;
- команды группового движения;
- команды broadcaster/moderator;
- предметы с реальными состояниями и эффектами;
- Channel Points, Bits, подписки и рейды;
- таблица лидеров и статистика участников;
- сохранение состояния между трансляциями;
- визуальный overlay для трансляции;
- звуковые эффекты и визуальная обратная связь;
- запись и воспроизведение последовательности команд;
- отдельный режим симуляции без Twitch;
- более сложное поведение через StateTree или Behavior Tree.
