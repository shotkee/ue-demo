# Twitch Bridge

`TwitchBridge` — локальная Node.js/TypeScript-программа между Twitch Chat и ареной Unreal Engine. Программа безопасно авторизуется в Twitch через Device Code Grant, получает чат через EventSub WebSocket, принимает одно соединение Unreal Engine, передаёт JSON-команды и получает их статусы.

По умолчанию сервер привязан только к loopback-адресу и слушает `ws://127.0.0.1:8080`. Доступ с приватного IPv4-адреса локальной сети включается отдельно.

## Требования

- Node.js 20.6 или новее;
- npm, входящий в установку Node.js;
- собранный проект Unreal Engine.

## Установка

Откройте PowerShell в корне репозитория и выполните:

```powershell
Set-Location .\Tools\TwitchBridge
npm ci
npm run build
```

В Terminal на macOS используются аналогичные команды:

```bash
cd Tools/TwitchBridge
npm ci
npm run build
```

## Создание и настройка `.env`

TwitchBridge читает слушаемый IP и порт из файла `.env`, расположенного рядом с `package.json`. После клонирования создайте локальный файл из отслеживаемого шаблона.

PowerShell:

```powershell
Copy-Item .env.example .env
```

Terminal на macOS:

```bash
cp .env.example .env
```

Если TwitchBridge и Unreal Engine работают на одном компьютере, оставьте безопасные локальные значения:

```dotenv
ARENA_BRIDGE_HOST=127.0.0.1
ARENA_BRIDGE_PORT=8080
ARENA_BRIDGE_ALLOW_PRIVATE_NETWORK_CONNECTIONS=false
```

Если TwitchBridge работает на Mac, а Unreal Engine — на Windows в той же локальной сети, укажите приватный IPv4-адрес Mac:

```dotenv
ARENA_BRIDGE_HOST=192.168.1.100
ARENA_BRIDGE_PORT=8080
ARENA_BRIDGE_ALLOW_PRIVATE_NETWORK_CONNECTIONS=true
```

Замените `192.168.1.100` на фактический адрес Mac. Его можно найти в `System Settings > Network > Wi-Fi > Details > TCP/IP`. После запуска событие `arena_bridge_listening` должно содержать ожидаемый адрес, например:

```json
{"event":"arena_bridge_listening","url":"ws://192.168.1.100:8080"}
```

Если IP Mac изменился, обновите одновременно `ARENA_BRIDGE_HOST` в `.env` и `Server URL` в Unreal Editor.

Файл `.env` предназначен только для локальных настроек и исключён из Git. OAuth-токены в `.env` и каталоге репозитория не записываются: мост хранит их в личном домашнем каталоге пользователя.

## Подключение Twitch после клонирования репозитория

Пользователю клона не требуется собственный Twitch Developer-аккаунт, регистрация нового приложения или `Client Secret`. В репозитории уже находится публичный `Client ID` приложения `Shotkee Arena Command Bridge`. Каждый пользователь авторизует свой Twitch-аккаунт, а секретные токены создаются отдельно только на его компьютере.

### Windows PowerShell

Из корня клонированного репозитория выполните:

```powershell
Set-Location .\Tools\TwitchBridge
npm ci
Copy-Item .env.example .env
npm run build
npm run auth
```

### macOS Terminal

Из корня клонированного репозитория выполните:

```bash
cd Tools/TwitchBridge
npm ci
cp .env.example .env
npm run build
npm run auth
```

Если `.env` уже существует, повторно копировать шаблон не нужно. Оставьте значение `TWITCH_CLIENT_ID`, находящееся в шаблоне: это общий публичный идентификатор приложения проекта. Параметры `ARENA_BRIDGE_HOST` и `ARENA_BRIDGE_ALLOW_PRIVATE_NETWORK_CONNECTIONS` настройте по разделу «Создание и настройка `.env`» выше.

Команда `npm run auth` напечатает адрес Twitch и временный код. После этого:

1. Откройте напечатанный адрес в браузере.
2. Войдите под Twitch-аккаунтом владельца канала, чат которого должен слушать мост.
3. Введите временный код, если Twitch его запросит.
4. Подтвердите доступ `user:read:chat`.
5. Вернитесь в Terminal или PowerShell и дождитесь события `twitch_authorization_ready`.

При стандартной настройке поля `authorizedUserId` и `channelUserId` должны совпадать. Это подтверждает, что мост авторизован под владельцем выбранного канала.

Мост запрашивает только минимальный scope `user:read:chat`. Scope `user:write:chat` не запрашивается, пока проект не отправляет ответы в чат.

Успешный результат содержит технические идентификаторы авторизованного пользователя и выбранного канала:

```json
{
  "event": "twitch_authorization_ready",
  "authorizedUserId": "123456",
  "authorizedUserLogin": "channel_login",
  "channelUserId": "123456",
  "channelLogin": "channel_login",
  "scopes": ["user:read:chat"]
}
```

По умолчанию мост использует канал авторизованного пользователя, поэтому `TWITCH_CHANNEL_LOGIN` следует оставить пустым. Явный логин другого канала можно указать без `#`, но для чтения его чата аккаунту могут понадобиться дополнительные права Twitch:

```dotenv
TWITCH_CHANNEL_LOGIN=channel_login
```

Проверить сохранённую авторизацию можно командой:

```powershell
npm run auth:status
```

## Получение Twitch Chat

После успешной авторизации запустите режим Twitch:

```powershell
npm run twitch
```

Он проверяет и при необходимости обновляет токен, подключается к Twitch EventSub WebSocket и создаёт подписку `channel.chat.message` версии 1. Одновременно запускается локальный WebSocket-сервер для Unreal Engine. На этапе `TW-3` Unreal Engine можно не запускать: получение чата проверяется независимо.

При успешном запуске журнал последовательно содержит события:

```text
twitch_authorization_ready
arena_bridge_listening
twitch_chat_subscription_created
twitch_eventsub_ready
twitch_mode_ready
```

Для проверки отправьте в чат выбранного канала разрешённую команду, например:

```text
!join
```

Мост должен вывести `twitch_chat_command_received`, а затем `twitch_chat_command_translated`. Обычные сообщения без `!` игнорируются. Повторная доставка одного сообщения Twitch не обрабатывается второй раз.

### Синтаксис команд чата

Префикс команд зафиксирован как `!`. Имя команды нечувствительно к регистру: `!join`, `!JOIN` и `!Join` равнозначны. Аргументы отделяются пробелами.

| Команда Twitch Chat | Действие в Unreal Engine |
| --- | --- |
| `!join` | Создать манекен автора с его текущим отображаемым именем и цветом ника Twitch |
| `!goto <point_id>` | Дойти до именованной точки шагом |
| `!run @<login-or-user-id>` | Добежать до манекена выбранного пользователя |
| `!hit @<login-or-user-id>` | Выполнить действие `punch` по выбранному манекену |
| `!go <object_id>` | Подойти шагом к объекту арены |
| `!stop` | Немедленно остановиться и очистить очередь команд автора |
| `!stop @<login-or-user-id>` | Остановить выбранного участника; только broadcaster/moderator |
| `!leave` | Удалить манекен автора с арены |
| `!leave @<login-or-user-id>` | Удалить выбранного участника; только broadcaster/moderator |

Для каждой команды исполнитель вычисляется только из стабильного Twitch User ID автора:

```text
chatter_user_id 80197074 -> actorId twitch:80197074
```

Обычный пользователь не может указать другой `actorId` и управляет только собственным манекеном. Исключение составляют административные варианты `!stop @...` и `!leave @...`: они разрешены только владельцу канала или модератору. Роль берётся из подписанного события Twitch EventSub, а не из текста сообщения. Повторный `!join` во время создания или после успешного появления манекена игнорируется и не отправляет второй `spawn`.

При `!join` мост также передаёт значение `color` из подписанного события Twitch как `displayNameColor` команды `spawn`. Unreal Engine применяет его только к основному тексту имени, сохраняя чёрную обводку. Если пользователь никогда не выбирал цвет ника и Twitch прислал пустое значение, поле не отправляется и используется белый цвет по умолчанию.

Цель участника обязательно начинается с `@`. Можно использовать актуальный Twitch-логин без учёта регистра, например `@ShotKee`, или числовой Twitch User ID, например `@80197074`. Для поиска по логину целевой пользователь должен сначала попасть в каталог моста, обычно отправив `!join`. Числовой ID преобразуется непосредственно в `twitch:<id>`.

Идентификаторы точек и объектов допускают латинские буквы, цифры, `_` и `-`. Мост преобразует их в нижний регистр; фактическое существование точки, объекта или манекена проверяет Unreal Engine.

Неизвестные команды, неверное количество аргументов и некорректные идентификаторы не отправляются в Unreal Engine. Причина записывается как `twitch_chat_command_rejected` с понятными полями `errorCode` и `message`.

### Ограничения и безопасность

По умолчанию Twitch Bridge применяет несколько независимых ограничений:

- пауза `750` мс между принятыми командами одного пользователя;
- не более `20` принятых команд в секунду для всего чата;
- не более `4` выполняемых или ожидающих команд для одного манекена;
- не более `20` Twitch-манекенов;
- не более `200` символов в сообщении-команде.

`!stop` является аварийной командой и проходит даже во время индивидуальной паузы или при заполненной очереди. Это позволяет немедленно остановить манекен и очистить его очередь. Неверные и отклонённые команды не передаются в Unreal Engine.

Парсер использует закрытый список команд и сам формирует все параметры протокола. Сообщение чата не может передать путь к ассету, имя функции Unreal Engine, произвольный `actorId`, режим движения или имя анимации. Для `!hit` действие жёстко задано как `punch`. Unreal Engine независимо повторно проверяет допустимые команды, поля JSON, цели и действия, ограничивает арену 20 участниками и очередь каждого участника 8 командами.

Лимиты можно уменьшить или осознанно увеличить в локальном `.env`. Для обычного запуска рекомендуется оставить значения из `.env.example`. Значение `ARENA_TWITCH_MAX_PARTICIPANTS` не следует поднимать выше ограничения `Maximum Participants` у `ArenaParticipantManager` в Unreal Engine.

Чтобы команды выполнялись визуально, откройте карту `Arena` в Unreal Editor и нажмите `Play`. Если Unreal Engine временно отключён, корректная команда помещается в ограниченную очередь переподключения.

При запуске мост также проверяет токен через Twitch и при необходимости обновляет его. Если доступ был отозван, refresh-токен истёк или изменился `Client ID`, журнал покажет событие `twitch_reauthorization_required` с предложением снова выполнить `npm run auth`.

При штатном `session_reconnect` мост переносит EventSub-сессию без повторного создания подписки. После обычного сетевого разрыва он подключается заново и создаёт новую подписку. Если Twitch отзывает подписку, мост останавливает текущий процесс с ошибкой, чтобы проблема не оставалась незаметной.

## Обратная связь и наблюдаемость

Для каждой отправленной команды мост создаёт корреляционную запись `twitch_command_lifecycle`. Одна и та же запись связывает:

- Twitch Message ID и Delivery Message ID;
- Twitch User ID, логин и отображаемое имя автора;
- пользовательскую команду чата;
- внутренние `RequestId`, `ActorId`, имя команды и параметры Unreal Engine;
- этап выполнения, результат, ошибку и прошедшее время.

Первая запись имеет `lifecycleStatus: "submitted"` и содержит полный объект `arenaRequest`. Следующие записи с тем же `requestId` показывают ответы Unreal Engine:

```text
submitted -> received -> accepted -> started -> completed
```

Вместо `completed` команда может завершиться как `rejected`, `failed` или `cancelled`. Команда, просроченная в очереди переподключения, получает `expired`; активная команда, отслеживание которой потеряно при разрыве Unreal-соединения, — `connection_lost`.

Пример завершённой записи:

```json
{
  "event": "twitch_command_lifecycle",
  "twitchMessageId": "message-id",
  "chatterUserLogin": "viewer",
  "requestId": "twitch:message-id",
  "actorId": "twitch:123456",
  "arenaCommand": "move_to_point",
  "lifecycleStatus": "completed",
  "elapsedMs": 1840,
  "errorCode": null,
  "message": "Participant reached the named point target."
}
```

Событие `bridge_connection_state` одновременно показывает состояния Twitch и Unreal Engine. Поле `ready` равно `true`, только когда оба соединения установлены. Счётчики `twitchReconnects` и `arenaReconnects` увеличиваются только после восстановления ранее работавшего соединения.

Событие `twitch_bridge_metrics` записывается при запуске, завершении и периодически во время работы. Оно содержит количество полученных сообщений-команд, отправленных и отклонённых команд, статусов Unreal, завершений, ошибок, отмен, истечений очереди, потерянных при разрыве команд и переподключений. Также в нём видны число активных команд, известных участников и текущие состояния соединений.

Интервал периодической сводки по умолчанию равен 60 секундам. Значение `0` отключает только периодическую запись; стартовая и итоговая сводки сохраняются.

В рамках MVP мост не отправляет сообщения обратно в Twitch Chat. Поэтому дополнительный scope `user:write:chat` не запрашивается и отдельный лимит ответов бота не требуется. Если ответы будут добавлены позднее, для них необходимо реализовать собственное ограничение частоты до включения этого scope.

Секретные access- и refresh-токены хранятся вне репозитория:

- macOS/Linux: `~/.arena-twitch-bridge/twitch-auth.json`;
- Windows: `%USERPROFILE%\.arena-twitch-bridge\twitch-auth.json`.

Не копируйте этот файл между компьютерами и не публикуйте его. Для независимого форка можно зарегистрировать собственное публичное Twitch-приложение и переопределить `TWITCH_CLIENT_ID` в `.env`; `Client Secret` для Device Code Grant не нужен.

## Автоматический smoke-тест без Twitch

1. Закройте старый PowerShell WebSocket-сервер, чтобы освободить порт `8080`.
2. Запустите мост:

   ```powershell
   npm run start:env -- --smoke
   ```

3. Дождитесь события `arena_bridge_listening`.
4. Откройте карту `Arena` в Unreal Editor и нажмите `Play`.

Панель должна показать `WS: Connected`. Мост создаст тестовый манекен и отправит его к точке `center`. Успешное завершение отмечается структурированной строкой с событием `smoke_completed` и сообщением:

```text
Twitch bridge smoke test completed successfully.
```

После теста соединение остаётся открытым. Для остановки нажмите `Ctrl+C`.

## Ручной режим без Twitch

Запустите мост без аргументов:

```powershell
npm run start:env
```

Вставляйте по одной JSON-команде в строку. Например:

```json
{"version":1,"requestId":"manual-spawn-alice","actorId":"manual:alice","command":"spawn","parameters":{"displayName":"Alice"}}
```

Если Unreal Engine временно отключён, команда помещается в ограниченную очередь. После восстановления соединения она отправляется автоматически. Просроченные команды удаляются, чтобы старые действия не выполнялись после длительного отключения.

## Запуск на отдельном Mac в локальной сети

По умолчанию сетевые подключения запрещены. Чтобы Unreal Engine на Windows подключался к мосту на Mac:

1. Узнайте локальный IPv4-адрес Mac в `System Settings > Network > Wi-Fi > Details > TCP/IP`.
2. В локальном `.env` на Mac укажите этот адрес и явно разрешите приватную сеть:

   ```dotenv
   ARENA_BRIDGE_HOST=192.168.1.100
   ARENA_BRIDGE_PORT=8080
   ARENA_BRIDGE_ALLOW_PRIVATE_NETWORK_CONNECTIONS=true
   ```

3. Запустите мост на Mac командой `npm run start:env -- --smoke`.
4. В Unreal Editor включите `Edit > Project Settings > Game > Arena WebSocket > Allow Private Network Connections`.
5. В расположенном рядом поле `Server URL` укажите `ws://192.168.1.100:8080`, заменив адрес на IP своего Mac.

При первом запуске macOS может запросить разрешение входящих подключений для Node.js — разрешите их для частной локальной сети. Не используйте `0.0.0.0`, публичный IP и проброс порта `8080` на роутере.

## Настройки

Настройки читаются из переменных окружения или локального `.env` при использовании `start:env`:

- `ARENA_BRIDGE_HOST` — loopback-адрес или явно разрешённый приватный IPv4-адрес, по умолчанию `127.0.0.1`;
- `ARENA_BRIDGE_PORT` — порт сервера, по умолчанию `8080`;
- `ARENA_BRIDGE_ALLOW_PRIVATE_NETWORK_CONNECTIONS` — разрешает конкретный приватный IPv4-адрес из `ARENA_BRIDGE_HOST`;
- `ARENA_BRIDGE_QUEUE_LIMIT` — максимальный размер очереди переподключения;
- `ARENA_BRIDGE_QUEUE_TTL_MS` — срок жизни команды в очереди;
- `ARENA_BRIDGE_STATUS_TIMEOUT_MS` — таймаут smoke-теста;
- `ARENA_BRIDGE_METRICS_INTERVAL_MS` — интервал периодической записи `twitch_bridge_metrics`, по умолчанию `60000` мс; значение `0` отключает периодическую сводку;
- `ARENA_BRIDGE_MODE` — `stdin`, `smoke` или `twitch`; команда `npm run twitch` явно выбирает режим `twitch` независимо от этого поля;
- `ARENA_TWITCH_USER_COOLDOWN_MS` — минимальная пауза между принятыми командами одного пользователя, по умолчанию `750` мс; значение `0` отключает только этот лимит;
- `ARENA_TWITCH_GLOBAL_COMMANDS_PER_SECOND` — общий предел принятых Twitch-команд за скользящую секунду, по умолчанию `20`;
- `ARENA_TWITCH_USER_QUEUE_LIMIT` — максимум активных и ожидающих команд одного манекена, по умолчанию `4`;
- `ARENA_TWITCH_MAX_PARTICIPANTS` — максимум Twitch-манекенов, известных мосту, по умолчанию `20`;
- `ARENA_TWITCH_MAX_MESSAGE_LENGTH` — максимальная длина сообщения-команды, по умолчанию `200` символов;
- `TWITCH_CLIENT_ID` — публичный идентификатор Twitch-приложения; в шаблоне уже задан общий идентификатор проекта;
- `TWITCH_CHANNEL_LOGIN` — необязательный логин выбранного канала; если поле пустое, используется канал авторизованного пользователя.

Если порт изменён, укажите тот же URL в Unreal Editor: `Edit > Project Settings > Game > Arena WebSocket > Server URL`.

## Проверки

```powershell
npm test
```

Тесты проверяют очередь до подключения, двустороннюю передачу сообщений, запрет второго активного соединения Unreal Engine, Device Code OAuth, обновление токенов, отсутствие `Client Secret` в запросах, создание подписки Twitch Chat, фильтрацию и дедупликацию сообщений, оба сценария переподключения EventSub, обработку отзыва подписки, строгий разбор чат-команд, права broadcaster/moderator, поиск Twitch-пользователей, идемпотентный `!join`, cooldown, общий rate limit, пользовательскую очередь, предел участников, длину сообщения, корреляцию статусов, метрики, состояния соединений, истечение команд и потерю отслеживания при разрыве.
